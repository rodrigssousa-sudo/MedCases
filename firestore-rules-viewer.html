ℹ️
Duas versões de helpers A versão em disco usa Custom Claims JWT para verificar admin (sem chamada extra ao Firestore). A versão submetida usa get() para buscar o role do usuário — adiciona uma leitura extra mas permite roles dinâmicos sem reemitir token.

Versão em Disco (firestore.rules — recomendada)

isAuthed()
function isAuthed() { return request.auth != null; }
Verifica se há um usuário autenticado na requisição.
isOwner(uid)
function isOwner(uid) { return isAuthed() && request.auth.uid == uid; }
Verifica se o usuário autenticado é o dono do recurso comparando o UID.
isAdmin()
function isAdmin() { return isAuthed() && ( request.auth.token .get('isAdmin', false) == true || request.auth.token .get('role', '') == 'admin' ); }
Usa custom claims JWT. Sem chamada extra ao Firestore. Requer setCustomUserClaims() no Auth.

Versão Submetida (usa get() no Firestore)

isAuth()
function isAuth() { return request.auth != null; }
Equivalente a isAuthed(), apenas renomeada.
isOwner(uid)
function isOwner(uid) { return isAuth() && request.auth.uid == uid; }
Idêntica à versão em disco.
userRole()
function userRole() { return isAuth() ? get(/databases/$(database) /documents/users/$(request.auth.uid)) .data.role : ''; }
⚠️ Faz uma chamada get() ao Firestore a cada avaliação. Lento e consome leituras extras.
isModerator()
function isModerator() { return isAuth() && userRole() in ['admin', 'master', 'supervisor']; }
Inclui o role supervisor como moderador. Não existe na versão em disco.
isAdmin()
function isAdmin() { return isAuth() && userRole() in ['admin', 'master']; }
Roles aceitos: admin e master. Busca via get() no documento do usuário.
💡
Recomendação Prefira a versão em disco com Custom Claims. Claims ficam no token JWT e não geram leituras extras ao Firestore. Para atualizar o role de um usuário, use o Firebase Admin SDK: admin.auth().setCustomUserClaims(uid, {'{'} isAdmin: true {'}'}).

Análise de Segurança

🔴
Regressão — get() no Firestore para verificar role A versão submetida lê /users/{uid} para obter o role. Um usuário mal-intencionado que consiga escrever em seu próprio documento poderia alterar o campo role e escalar privilégios, a menos que a regra de write de /users/{uid} bloqueie isso. Verifique se o campo role não pode ser escrito pelo próprio usuário.
⚠️
Custo de leitura Cada chamada a isModerator() ou isAdmin() na versão submetida dispara um get() ao documento do usuário. Em coleções com múltiplas regras que chamam essas funções, uma única requisição pode acumular 2–3 leituras extras, aumentando custos e latência.
✅
Versão em disco é mais segura Custom Claims no JWT não custam leituras adicionais, são verificados localmente no token e não podem ser alterados pelo usuário final sem o Firebase Admin SDK.
